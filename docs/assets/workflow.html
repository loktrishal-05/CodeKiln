CodeKiln workflow: from a repository to a sealed task package

Every step ends in a gate. The model only proposes; code and execution decide. A failure carries its real evidence back to the writer, at most twice.

1
PLAN
CODE, NO MODEL
  • Ingest the repo at a pinned commit; nothing from it is executed
  • Import graph, then slots in 5 categories
  • Diversity guard rejects overlap of 0.4 or more
  • Difficulty dial L1 / L2 / L3
Gate: passes the diversity guard
➜
2
WRITE
MODEL PROPOSES
  • Repo Scout adds real signatures and existing test names
  • The model writes the instruction, the tests and edits (where code goes)
  • Code builds the diff from the real files
Gate: git apply --check passes
➜
3
STATIC CHECKS
CODE DECIDES
  • validate: names, test ids, no edits to tests or CI
  • RTM audit: every requirement has a real test
  • Blind-reader lint of the only file the agent sees
Gate: package written, BLIND_READER_OK
the package then runs in Harbor, the same commands the judges use
4
EXECUTE
HARBOR, FRESH SANDBOX
  • A ×1: record the regression set
  • B ×3 (nop): feature tests must fail
  • C ×3 (oracle): everything must pass
  • Flaky existing tests are quarantined
Gate: reward 0.0 then 1.0, per test
➜
5
STRENGTH
HARBOR
  • No-op, stub and partial solutions: all killed
  • Semantic and model-written wrong solutions: at least 80% killed
  • Red team: 4 cheat attempts must score 0.0
Gate: the tests catch wrong solutions
➜
6
SEAL
CODE
  • Scrub: one orphan commit, diff policy, secret scan
  • Receipt and SHA-256 manifest
  • Atomic promote: never half-visible
Gate: every earlier gate passed

Evidence-based repair loop

A failure at State C or in the mutation probes goes back to step 2 with the real evidence: the pytest output (or the log's end if import click broke) or the names of the wrong solutions that still passed. At most 2 repairs, then the candidate is rejected. The model is never asked whether its work is good.

PACKAGED

Sealed Harbor task: nop scores 0.0, oracle scores 1.0, with receipt, audit and manifest.

REJECTED

Kept in the ledger with the exact gate and reason, and shown on the dashboard.
Ledger Every transition, every Harbor trial and every paid model call is recorded, so a run can stop and resume at any point.
